# PLAYTEST — D-204/D-206 엔지니어 터렛 건설 (BUG-204) / 한국어

착석 1회(약 5–8분)로 아래 항목을 **한 번에** 판정합니다. ②~④는 그립이 게임의 어느 표면으로 들어가는지,
⑤는 이 버그의 본체(설치 확정), ⑦~⑨는 부작용(D-057 보존·사이드 이펙트)입니다.

- 준비: 엔지니어로 플레이 중이어야 합니다(터렛 스킬 보유). 설치본 config `vhvr-openxr-host.json`의
  `TurretCycle` 값(기본 `Stick`)을 기록해 두십시오 — 이 값이 이 세션의 A안입니다.
- 로그: 세션 후 `artifacts\headset-d087\<태그>\run\hand-aim.json`의 `input.turret.*`와 `padSent`를 확인합니다.

| --- | --- | --- |
| ① | 오른쪽 스틱을 **아래로** 당겨 건설 모드 진입 | 건설 UI + **파란 고스트 터렛**이 보인다 (사용자 확인 완료 → 위치 축은 정상) |

| ⑤ | **양쪽 그립을 동시에** 누르고 1초 유지 | 파란 고스트 위치에 **실제 터렛이 설치**된다 (쿨타임 표기/터렛 등장). 놓으면 즉시 멈춘다 — 두 번째 설치가 연속으로 나가면 실패 |
| ⑥ | ⑤ 직후 트리거(주 발사)를 당긴다 | ⑤가 성공했는데도 트리거로는 설치되지 **않는다면** 그대로 보고(모드의 발사 경로가 `Fire` 액션을 안 올린다는 증거 → 남은 `Fire` 표면 보강 필요). 반대로 트리거만으로 설치되면 `Fire` 경로가 필드에서도 읽힌다는 뜻 |

| ⑧ | 건설 모드를 나간 뒤(특수능력 다시/해제) **그립을 눌러 본다** | **아무 일도 없어야 한다** (D-057 보존 확인). 여기서 뭔가 일어나면 즉시 보고 |

## 영수증에서 확인할 것
- `input.turret.modeFrames > 0` (게임이 건설 모드라고 말한 프레임 수) — 0이면 `is_turret_mode` 읽기 실패(`input.turret.error`).
- `input.turret.stepsBack` / `stepsForward`가 실제로 누른 횟수와 같은가 (그립 입력이 네이티브에서 오는지 확인).
- `input.turret.confirms`가 ⑤ 횟수와 같은가, `input.turret.confirmHeld`가 마지막 상태.
- `input.padSent`가 증가(패드 살아 있음) / `input.padError = null`.

## 이 테스트가 판정하지 않는 것
- 터렛 종류가 **스킬로 해금**된다는 사실(게임 데이터: `skill_desc_engineer_9/17/23`, 성취 `..._2` = "all 4 turrets")은
  이미 확정이며 여기서 재검증하지 않습니다.
- 설치 **위치**의 정확도(고스트 위치와 실제 설치 위치가 같은지는 눈으로만 판단).
