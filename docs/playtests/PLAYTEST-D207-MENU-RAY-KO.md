# PLAYTEST — D-207 메뉴 오른손 ray + 장시간 안정성 (한 번 착석)

> 목적: Native hands ABI 수정 후 오른손 메뉴 ray가 실제 컨트롤러를 따라가는지 확인하고, 동일 조건에서 CoreCLR 크래시 재발 여부를 관찰한다.
> 준비: 수정된 Extras가 설치된 상태, 왼손/오른손 컨트롤러, 메인 메뉴. 이번 수정은 **Extras만** 바꾸며 Stage0/native/config는 건드리지 않는다.
> 중요: 자동화 테스트는 레이아웃만 확인한다. 시각 동작과 crash-free 판정은 사람이 한 번 실행해야 한다.

## 실행 전 (헤드셋 없이)
1. 게임이 꺼져 있는지 확인한다.
2. 설치한 `VhvrExtras.dll`이 54,272 B / SHA256 `B4AD024D6908D52C76FA8F054A34D40E4C0ED9780C045731EA8B3F044F2FA3C1`인지 확인한다.
3. `BepInEx\\LogOutput.log` 이전 실행분을 따로 보존하고 새 실행의 시작 시각을 기록한다.
4. 게임을 직접 실행한다. 에이전트/스크립트는 게임을 실행하지 않는다.

| # | 확인 항목 | 기록 |
|---|---|---|
| A1 | 왼쪽 ray가 보이고 왼손을 따라가는가? (회귀 확인) | 예 / 아니오 |

게임을 실행한 김에 평소 플레이를 이어서 세션을 관찰한다(추가 헤드셋 착석은 요구하지 않음). 크래시를 일부러 유발하지 않는다.

## 종료 후 (헤드셋 없이)
1. 정상 종료했는지/갑자기 꺼졌는지와 종료 시각을 적는다.
2. 새 `Application Error 1000`이 있으면 발생 시각, faulting module, exception code, offset을 보존한다.
3. 새 `BepInEx\\LogOutput.log` 마지막 30줄과 `artifacts\\d207-install\\` 배포 영수증을 함께 보존한다.
4. 크래시가 없었던 경우에도 이를 **이 한 세션 동안 재발 없음**으로만 기록한다(영구 해결 증명 아님).

## 결과 형식

```text
A1 ___ A2 ___ A3 ___ A4 ___ A5 ___
실행 시작 ___ / 종료 ___ / 정상 종료 또는 크래시 ___
새 Application Error 1000 없음/있음 ___ (시각·module·exception·offset)
특이사항 ___
```

## 판정
- **시각 PASS**: A1–A5 모두 예. 메뉴가 보이지 않았거나 입력을 못 한 항목은 NOT TESTED/FAIL로 분리한다.
- **시각 FAIL**: 오른 ray가 숨거나 틀린 손을 따름, 또는 버튼 선택 불가. 로그만으로 통과 처리하지 않는다.
- **안정성 관찰**: 이 한 실행 중 Application Error 1000 없음이면 해당 세션에 한해 미재현. 재발하면 crash 원인을 여전히 미확정으로 두고 최신 이벤트/로그를 분석한다.
