## 🎯 GOAL — EDF6 스타일 표시 모드 (시작부터 VR + 검은 배경 + 평면 스크린 → 스테이지 진입 시 VR 전환)
- **동기(사용자 요청 2026-10-15)**: 게임 시작부터 VR로 들어가고, 검은 배경에 눈앞 **평면 스크린**에 메뉴를 띄운 뒤, 스테이지 진입 시 **스테레오 VR로 자연 전환**. (EDF6 VR 모드와 같은 연출)
- **왜 지금은 안 되는가(정확한 이유)**: 우리 모드는 **카메라 계층**(게임 카메라를 복제해 양안 생성)에 붙어 있어 **게임의 최종 합성 화면(backbuffer)을 잡지 못한다**. EDF6류 모드는 **최종 화면 출력(present/backbuffer) 계층**에 붙어 "완성된 2D 화면 한 장"을 quad에 붙이기만 하면 되므로 평면 스크린이 자연스럽게 나온다. (EDF6도 공식 VR 아님 — 모드임. 차이는 "엔진 지원"이 아니라 **후킹 지점**이다.)
- **접근**: 네이티브 호스트(`VhvrNativeHost`)에 **D3D11 Present/backbuffer 캡처**를 추가 → 캡처 프레임을 메뉴 동안 **검은 배경의 quad**로 표시 → 스테이지 진입 시 quad 제거 + 스테레오 VR 전환(기존 `MenuFirst` 핸드오프 재사용).
- **재사용할 이미 확보한 지식(실측)**:
  - `TOOL-092`: 게임이 내장 셰이더를 스트리핑 → 플러그인 셰이더는 **후보 목록 + 로드된 셰이더 스캔 폴백** 필요.
  - `TOOL-093`: 메뉴 씬 언로드 시 카메라 파괴 → 렌더 스케줄이 예외로 호스트 종료 → **즉시 재획득/그 프레임 스케줄 스킵** 필요.
  - `TOOL-094`: **URP는 플러그인이 만든 카메라를 자동 렌더하지 않음** → 매 프레임 수동 `Render()`로 해결. **렌더 텍스처는 정상 생성됨을 실측 증명**(nonBlack 920k/921k).
  - **아직 미확인**: 눈 카메라를 layer 마스킹했을 때 **quad가 실제로 눈 이미지에 그려지는지**(패널 시도에서 확인 못함) — 이 목표의 최대 리스크.
- **단계(제안)**:
  1. 네이티브 호스트에 backbuffer 캡처(프레임 1장) 추가, 텍스처/파일로 노출.
  2. 플러그인에서 그 텍스처를 받아 quad에 표시(검증된 수동 Render 방식 재사용).
  3. 눈 카메라 검게 마스킹 + quad 레이어만 보이게 → **이 경로가 실제로 렌더되는지 검증**(최대 리스크).
  4. 실기기 확인: 검은 배경 + 평면 메뉴 화면.
  5. 스테이지 진입 시 quad 제거 + 스테레오 VR 전환(기존 핸드오프).
- **폴백**: 현재의 **월드스페이스 캔버스(월드 + UI, 월드 고정)** 방식 유지 — 이미 잘 보임.
- **선행/순서**: 독립 작업. 단 현재 진행 중인 **① 월드 고정 ② 레이저/선택 검증**을 먼저 끝낸 뒤 착수 권장.

### B(지연 초기화) 실현성 조사 결과 — 2026-10-14 (실현 불가)
- 디컴파일 근거: `OpenXrHost.Initialize()`는 **일회성 단일 메서드**로 ① 설정 검증 ② 게임플레이 카메라 대기(루프) ③ 카메라/눈 준비 ④ 손/무기 통합 생성 ⑤ `configured=true` 를 모두 수행한다. `Update`는 `!configured`일 때 단 한 번 호출한다.
- 손/무기 통합은 **`if (Config.GameplayOnly)` 경로에서만** 만들어지고, `HandAim && !GameplayOnly`면 **예외**를 던진다 → 메뉴 모드에서 나중에 손을 붙이는 진입점이 **없다**.
- B로 하려면 (i) 일회성 `Initialize` 재호출(카메라·눈·세션 재구성 위험) 또는 (ii) extras에서 `HandAimDriver` 생성·`InstallUiRender`·`Tick`·스냅 회전(호스트 개인 필드 다수 리플렉션)을 **통째로 재구현**해야 함 = 사실상 호스트 복제.
- 대안적 IL 트랜스파일(약 440줄 메서드의 `throw`/분기 무력화)도 **고위험·저신뢰**.
- **결론**: A(소스 복구)가 유일하게 견실한 경로. 다행히 소스 손상은 **2개 파일·전부 구문 오류**이고 `ilspycmd`로 원본 복원이 가능하므로, 실제 기능 변경 자체는 작다(검증 조건 완화 + 메뉴 분기).
- 부수 발견: 현재 MenuFirst는 설정 검증 예외로 **초기화 실패**(`TOOL-091`).
